# 2.2. Requisitos suplementares

Restrições que se aplicam ao sistema como um todo, e não a uma função específica.

| Nome | Restrição | Categoria | Desejável | Permanente |
|---|---|---|:---:|:---:|
| **S1** Interface web | O sistema terá uma interface web responsiva, que se adapta a telas de computadores e smartphones e pode ser usada pelo navegador, sem necessidade de instalação. | Interface | ( ) | (X) |
| **S2** Aplicativo mobile | O sistema terá também um aplicativo nativo para smartphones (Android e iOS), com as mesmas funcionalidades da versão web. | Interface | (X) | ( ) |
| **S3** Acesso aos dados via API | O acesso ao banco de dados deve ser feito através de uma API REST, de modo que as aplicações web e mobile compartilhem as mesmas funcionalidades e regras de negócio. | Implementação | ( ) | (X) |
| **S4** Perfis de usuário | Cliente – qualquer usuário cadastrado; busca prestadores, solicita, acompanha e avalia serviços.<br>Prestador – cliente que ativou o perfil de prestador; além das funções de cliente, gerencia serviços, disponibilidade e solicitações recebidas.<br>Administrador – mantém as categorias e modera denúncias. Contas de administrador são criadas apenas por outro administrador. | Segurança | ( ) | (X) |
| **S5** Idade mínima | O sistema deve ser usado somente por maiores de 18 anos. | Legal | ( ) | (X) |
| **S6** Proteção de dados pessoais | O tratamento de dados pessoais (incluindo CPF e localização) deve seguir a Lei Geral de Proteção de Dados (Lei nº 13.709/2018): coleta apenas dos dados necessários, finalidade informada, consentimento e direito de acesso, correção e exclusão. | Legal | ( ) | (X) |
| **S7** Segurança da comunicação e das senhas | Toda comunicação entre as aplicações e o servidor deve usar HTTPS (TLS). As senhas são armazenadas apenas na forma de hash, com algoritmo próprio para senhas (ex.: bcrypt). | Segurança | ( ) | (X) |
| **S8** Intermediação do serviço | A plataforma apenas aproxima clientes e prestadores: não processa pagamentos nem se responsabiliza pela execução do serviço. Preço e forma de pagamento são combinados diretamente entre as partes, conforme os Termos de Uso. | Legal | ( ) | ( ) |
| **S9** Idioma e formatos | Interface em português do Brasil; valores em reais (R$), datas no formato dd/mm/aaaa e distâncias em quilômetros. | Interface | ( ) | (X) |
| **S10** Disponibilidade do sistema | O sistema deve estar disponível em 99% do tempo de cada mês, excluídas as janelas de manutenção programada. | Confiabilidade | (X) | ( ) |
| **S11** Cópias de segurança | Deve ser feito backup diário do banco de dados, mantendo as cópias dos últimos 30 dias. | Confiabilidade | (X) | (X) |
| **S12** Falha de serviços externos | Se a API de geocodificação ou de CEP estiver indisponível, o sistema deve informar o usuário e permitir que ele tente novamente, sem perder os dados já digitados. | Confiabilidade | (X) | (X) |
| **S13** Persistência geoespacial | A persistência será feita em banco de dados relacional com suporte a consultas geoespaciais (ex.: PostgreSQL com PostGIS), permitindo a busca de prestadores por raio de distância. | Implementação | ( ) | ( ) |
| **S14** Distribuição | A versão web será hospedada em um serviço de nuvem; o aplicativo mobile será distribuído pelas lojas oficiais (Google Play e App Store). | Empacotamento | (X) | ( ) |
| **S15** Acessibilidade | A interface deve seguir as diretrizes WCAG 2.1, nível AA: contraste adequado, textos alternativos em imagens e navegação por teclado na versão web. | Interface | (X) | ( ) |
